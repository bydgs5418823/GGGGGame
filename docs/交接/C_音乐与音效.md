更新日期为 2026-11-08。B 下发音乐和音效的数量、文件名、属性、事件与验收，C 完成制作、导出和游戏内试听。

## 1. 本轮明确交付

交付 19 个音效文件、1 首循环音乐、全部 WAV 母版、Studio One 可编辑工程、必要依赖说明和实际测量表。

B 的统一清单见[交付总表](B_策划_API与协调.md)第 4 节，事件来源和字段见[API 契约](../API与联调契约_v0.2.md)第 8 节。运行时音频放入 who-sent-this-guy/assets/audio，母版和可编辑工程放入 source_assets/audio。

所有参数是 B 的灰盒初稿。C 制作并回交测量值、听感和建议，B 汇总后发布采用值。人物和 UI 由 D 接入，车辆、物体接触和交付由 E 接入。

## 3. 技术属性和制作规则

| 属性 | 本轮采用初稿 |
|---|---|
| 母版 | 48 kHz、24-bit PCM WAV |
| 短音效与循环音效运行时文件 | 48 kHz、16-bit PCM WAV，声道按上表 |
| 音乐运行时文件 | Ogg Vorbis，记录实际质量设置，并保留 WAV 母版 |
| 峰值余量 | 母版建议真峰值不超过 -1 dBTP，提交实际测量值 |
| 起音 | 操作短反馈清除无意前置静音，起音清楚 |
| 尾音 | 保留有意尾音和混响，起止处无意外爆音 |
| 循环 | 标明起止采样位置和秒数，边界落在有效长度内 |
| 变体 | 同组强弱范围相近，材质特征一致，可避免连续重复相同样本 |
| 调音高 | 碰撞变体允许初稿 ±1 半音，音乐和操作提示使用原音高 |
| 插件依赖 | 记录 Studio One、Serum 2 及使用插件的具体版本，保留可直接播放的导出文件 |
| 素材来源 | 录制、自制、采样或生成来源随工程交付，外部素材附使用说明 |

游戏内响度关系由 B、C 试听一局灰盒后统一标定，单文件峰值和整局混音分别记录。

## 4. 已指定的播放属性

| 类别 | 位置与分组 | 参考/最远距离初值 | 并发与启停 |
|---|---|---|---|
| 发动机两层 | 车头 AudioEngine，SFX | 3 / 25 m | 每车各一条循环，车辆激活后开始，销毁、重置或停用后停止 |
| 轮胎滑移 | 车辆接地位置，SFX | 2 / 20 m | 每车一条聚合滑移声，强度归零后 0.15 s 淡出 |
| 木/金属/重物撞击 | 事件接触位置，SFX | 2 / 18 m | 同对象最多 2 条短声，连续接触最短间隔 0.12 s |
| 圆桶滚动 | 圆桶位置，SFX | 1 / 12 m | 每桶一条，滚动停止后 0.15 s 淡出 |
| 抓取/松手 | 操作对象位置，SFX | 1 / 8 m | 每次成功操作一次，清理原因可抑制松手声 |
| 固定/解除 | 对应货物位置，SFX | 1 / 10 m | 每次状态实际变化一次 |
| 交付/完成/失败 | 本地 2D，UI | 不适用 | 按确认事件播放，失败只给请求者 |
| 音乐 | 本地 2D，Music | 不适用 | 每个客户端一条，关卡退出或替换时淡出 |

上表距离单位为 m，衰减和音量关系在真实场景试听。步行的听音参考使用本地人物 EyeStanding 或 EyeCrouching，驾驶使用车辆 AudioListenerDriver，乘员使用其座位眼点。D、E 随镜头上下文更新听音参考，第三人称观察镜头拉远时仍保留驾驶员位置的声音关系。

## 5. 事件与持续参数映射

| 来源 | 参数或事件 | 播放结果 |
|---|---|---|
| VehicleSnapshot | EngineLoad01 在 0 至 1 | 低值主用 idle，高值增加 load，C 提供两层混合试听 |
| VehicleSnapshot | SkidIntensity01 在 0 至 1 | 大于初稿阈值 0.1 时渐入滑移声，低于 0.05 时退出，避免抖动启停 |
| ObjectImpact | SurfaceId、Intensity01、PositionM | 选择对应材质组，强度调整音量，按 EventId 去重 |
| 滚动状态 | RollingStarted / RollingStopped | 对应圆桶实例启动或停止滚动循环 |
| 交互 | CargoGrabbed / CargoReleased | 每位玩家成功操作后的反馈，共同抓取可以产生两次不同参与事件 |
| 固定 | CargoSecured / CargoUnsecured | 状态变化一次，播放一次 |
| 回合 | CargoDelivered / RoundCompleted | 交付和完成分别一次确认 |
| 失败 | RequestDenied 与结果码 | 请求者听到一次失败音，并由 UI 提供文字原因 |
| 生命周期 | 对象销毁、断线清理、RoundReset、退出场景 | 停止相应持续声，移除旧实例关联 |

相同网络事件重传使用同一 EventId，接收端只播放一次。两名玩家各自成功加入同一对象属于两个有效事件。共享状态确认结果由程序端提供，C 检查听感与播放次数。

EngineLoad01、滚动与冲击映射由 B 在物理标定批次发布。C 反馈事件强弱不清或音量不连贯的位置，B 统一调整声音映射。

## 7. C 交回 B 的明确成果

1. 19 个运行时音效文件和 1 个音乐文件，名称与本单逐项对应。
2. 对应 WAV 母版、Studio One 工程、使用音源与插件的说明。
3. 实测表，逐项记录采样率、编码、声道、时长、循环点、峰值、响度测量方式和文件大小。
4. 两层发动机混合和音乐循环的独立试听版本。
5. 三批试玩和修订结果，标明循环、停止、多人重复和相机变化的检查结论。

B 接收后维护统一资产状态和映射版本。当前音频成品处于待制作状态。

格式和循环导入参考[官方音频导入说明](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_audio_samples.html)，实际采用的压缩与导入设置随接入记录交付。
